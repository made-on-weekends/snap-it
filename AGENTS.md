## Rules of Engagement

These rules are the agent's first read every session:

1. **Do** conform to `.editorconfig` formatting rules (2-space indentation, LF line endings, UTF-8 charset, trailing whitespace trimming) across all code, markup, and docs.
2. **Do** follow the canonical design system in `docs/DESIGN.md` and use CSS custom properties from `assets/theme.css` / `assets/tokens.json`. Never invent ad-hoc hex color codes.
3. **Do** modify `manifest.json` as the single source of truth when updating extension permissions or metadata, then run `npm run manifests` to synchronize `manifest.chrome.json` and `manifest.firefox.json`. Never hand-edit derived manifests.
4. **Do** check `docs/DECISIONS.md` before changing architectural patterns or capture workflows.
5. **Do** ensure `chrome.debugger` sessions are always detached cleanly in all success and failure branches in `service-worker.js`.
6. **Don't** introduce external runtime NPM packages or heavy build frameworks without a formal `docs/DECISIONS.md` entry. SnapIt is intentionally zero-runtime-dependency vanilla JS.
7. **Don't** commit secrets, API keys, or `.agents/mcp_config.json` to Git. Keep `.agents/` ignored.
8. **Don't** edit files in the do-not-touch zones below.

## Stack

- **Platform:** Cross-browser WebExtension (Chromium Manifest V3, Firefox MV2/MV3)
- **Language:** Vanilla JavaScript (ES2022+ / ES Modules)
- **UI & Styling:** Vanilla HTML5, CSS3 with Design Tokens (`assets/theme.css`)
- **Graphics & Annotation:** HTML5 2D Canvas API
- **Capture Engines:** Chrome DevTools Protocol (`chrome.debugger`), `chrome.tabs.captureVisibleTab`, `navigator.mediaDevices.getDisplayMedia`
- **Storage:** Chrome Storage API (`chrome.storage.local`, `chrome.storage.session`), IndexedDB (`SnapItDB`) via `storage-helper.js`, File System Access API
- **Build / Packaging:** Shell scripts (`scripts/build.sh`, `scripts/build-chrome.sh`, `scripts/build-firefox.sh`) + Node.js manifest generator (`scripts/generate-manifests.js`)
- **Package Manager:** `npm` (manifest scripts & linting)

## Commands

```bash
# Generate browser-specific manifests from manifest.json
npm run manifests

# Build / package both Chrome and Firefox extensions into dist/
npm run build

# Build Chrome distribution only (into dist/chrome)
npm run build:chrome

# Build Firefox distribution only (into dist/firefox)
npm run build:firefox

# Lint Firefox extension using web-ext
npm run lint:firefox
```

## Conventions

- **Manifest Single Source of Truth:** `manifest.json` contains universal fields. Browser-specific overrides are handled via `scripts/generate-manifests.js`.
- **Code Style & Formatting (.editorconfig):** 2 spaces indentation for JS/HTML/CSS/JSON, LF line endings, UTF-8 charset, trim trailing whitespace.
- **Design Tokens:** Always reference CSS variables from `assets/theme.css` (`var(--accent)`, `var(--surface)`, `var(--text)`, etc.). Source of truth is `docs/DESIGN.md` synced with `/home/asif/Documents/brands/snapit`.
- **Async Pattern:** Use `async`/`await` with explicit `try...catch` blocks for asynchronous WebExtension and IndexedDB operations.
- **Error Handling & Cleanup:** When using `chrome.debugger.attach`, guarantee detachment in `finally` blocks to prevent browser debugger warnings or hung tab state.

## Do-Not-Touch Zones

- `dist/` — generated build artifacts; never edit or commit.
- `manifest.chrome.json` & `manifest.firefox.json` — generated by `npm run manifests`.
- `assets/svg/` — canonical brand SVGs; source of truth is `/home/asif/Documents/brands/snapit`.
- `assets/theme.css` & `assets/tokens.json` — synchronized from brand repository; do not edit directly without updating brand specifications.
- `.agents/mcp_config.json` — local machine credentials and configuration; strictly gitignored.
